# lnwjing v4.44.0 Tools, Lossless Logs, and Runtime Integrity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILLS: Use `subagent-driven-development` to implement this plan task-by-task, `test-driven-development` for every behavior change, `systematic-debugging` for unexpected failures, `impeccable` for the Tools/Logs UI, and `verification-before-completion` before any completion claim. The user explicitly authorized delegated implementation, scoped commits, one push to `dev`, and a local Windows installer build. Do not tag, publish, create a GitHub Release, or install the build for the user.

**Status:** Authorized for execution on `dev`. Source baseline was fast-forwarded to `origin/main` at `21bcbbf` before implementation; `dev` is currently one commit ahead of `origin/dev` for that fast-forward.

**Goal:** ออกชุดทดสอบภายในเครื่องสำหรับ lnwjing `4.44.0` ที่ (1) เก็บและส่งออกชื่อไฟล์/ชื่อเครื่องมือของแต่ละ log event ครบทุกตัวโดยไม่ใช้ `(+N)`, (2) ย่อเฉพาะการแสดงผลแต่ละแถวและกด “ดูเพิ่ม/แสดงน้อยลง” ได้, (3) แสดงสถานะ Tools อย่างตรงความจริงและอ่านง่าย, (4) แยก Browser “ต้องเปิดใช้งาน” ออกจาก “ต้องตั้งค่า”, (5) ทำ Accessibility / Computer Use / UI Target Action ให้ผ่าน integrity ของ packaged runtime จริง, และ (6) ทำ `agent_swarm_run` เป็น Codex-backed read-only tool ที่ opt-in, จำกัดขอบเขต/จำนวน, เป็นเจ้าของงาน และยกเลิกงานที่ยังมี verified runtime handle ได้

**Architecture:** Activity Tracker จะเก็บ `targetSummary` แบบสั้นควบคู่กับ full detail ที่ผ่าน shared redaction และ persist ครั้งเดียวใน SQLite. Work Log/Live Log rows ส่งเพียง immutable detail reference, item count, preview และ legacy flag; renderer lazy-load ทีละรายการ ส่วน copy/export/query resolve และ stream ข้อมูลเต็มจาก main process โดยไม่อิง DOM ที่ย่ออยู่. Tool Catalog จะเพิ่ม reason/delivery state แยกจาก readiness หยาบเพื่อไม่ตีความ runtime ที่ปิดว่าไม่ได้ setup. Windows capability bridge จะถูก stage เป็น byte artifact เดียวก่อน hash/build/package และ installer verifier จะพิสูจน์ source = staged = manifest = app expectation = packaged bytes พร้อมเรียก probe จาก packaged runtime จริง. Agent Swarm จะเป็น deep module read-only แยก มี durable ledger/terminal result, Codex quota opt-in, trusted approval, enforced read-only sandbox และ per-swarm concurrency; active child ที่ข้าม app restart จะรายงาน `termination_unverified` โดยไม่อ้างว่ายกเลิกหรือกู้ handle ได้.

**Tech Stack:** TypeScript, React, Electron, Node.js 24, SQLite WAL, MCP, PowerShell capability bridge, electron-builder, Vitest, Playwright, pnpm `10.15.0`

## Global Constraints

- ทุกชื่อใน collection ของ `read_many_files` และ `tool_batch` ต้องถูกเก็บหลัง redaction ครบตาม schema limit และลำดับเดิม; ห้ามใช้ `(+1)`, `(+2)`, `(+N)` กับ event ใหม่
- การย่อเป็น presentation-only ต่อรายการ: ปุ่มต้องมี `aria-expanded`, `aria-controls`, focus ring และข้อความไทย/อังกฤษ; เมื่อขยายต้องเห็นทุก item ของ event นั้น
- Copy และ export ต้องใช้ full structured model เสมอ ไม่ว่ารายการจะย่อหรือขยายอยู่
- ห้ามแนบ full item arrays กับ dashboard rows หรือ LogHub buffer ทุกแถว; row contract ใช้ `{ detailRef, itemCount, preview, legacyIncomplete }` และ lazy-load ได้ครั้งละหนึ่งรายการ
- SQLite เป็น full-detail authority เพียงแห่งเดียว; append-only `mcp-activity.log` เก็บ summary/reference เท่านั้นและห้ามทำสำเนา array ขนาดใหญ่
- Work Log identity ต้องแยก persisted `audit:<eventId>` กับ `inflight:<callId>`; export จับ immutable identity list ตอนคลิก และถ้า call จบระหว่าง export ให้ resolve started audit event ด้วย `callId` โดยไม่ทำรายการหาย
- Query/search ต้องทำใน main process และค้นชื่อ item ที่ซ่อนอยู่ได้โดยคืนเฉพาะ matching row IDs; ห้าม hydrate full detail ทุกแถวเพื่อค้นหา
- ข้อจำกัด retention ของหน้าจอ (จำนวน event ที่เก็บ) เป็นคนละเรื่องกับความครบของ item ภายใน event; งานนี้รับประกัน **all items per retained event**
- Log เก่าที่ถูกบันทึกเป็น `(+N)` ไปแล้วกู้ชื่อที่หายไม่ได้ ต้องแสดงคำเตือน “รายละเอียดเดิมไม่ครบจากเวอร์ชันก่อน” และห้ามสร้างชื่อสมมติ
- Redaction, bounded IPC, max event count และ file-size safety ต้องยังอยู่; แก้ truncation ด้วย structured bounded fields ไม่ใช่ปล่อย string ไม่จำกัด
- `needs_setup` ใช้เมื่อผู้ใช้ต้องติดตั้ง/ตั้งค่าจริงเท่านั้น; Managed Browser ที่ติดตั้งแล้วแต่ปิดอยู่ต้องเป็น `runtime_not_ready` พร้อม CTA “เปิด Managed Browser”
- `unknown` ใช้เฉพาะ probe timeout/crash/invalid response/integrity uncertainty; ห้ามใช้แทน planned, disabled, unsupported หรือ runtime stopped
- สี selected state ต้องผ่าน WCAG AA สำหรับตัวเลขและ label, เห็น focus ชัด และไม่พึ่งสีอย่างเดียว
- ห้ามลดความปลอดภัยด้วยการข้าม hash, เชื่อ manifest ที่แก้ได้ขณะ runtime หรือปิด PowerShell bridge integrity check
- `agent_swarm_run` ต้องไม่ปรากฏใน `tools/list` เมื่อ `codexToolsEnabled=false`; ทุก `start`/`cancel` ต้องผ่าน trusted host approval และ mutation policy
- Agent Swarm v4.44.0 รองรับ 1–4 read-only agents, default concurrency 2; reject `workspace-write` และ path-level write claims ที่ enforce ไม่ได้
- ห้าม auto-retry หรือสร้าง agent เพิ่มนอก request; partial launch ต้องหยุด children ที่เริ่มโดย swarm นั้นและรายงาน outcome รายตัว
- Swarm ledger ห้ามเก็บ prompt plaintext; เก็บ owner, digest/length, runtime handle identity, durable output/result location, timestamps และ terminal/cancellation state เท่านั้น
- หลัง restart terminal receipt/output ที่ persist แล้วอ่านได้ตาม owner; active child ที่ไม่มี verified live handle ให้สถานะ `termination_unverified` และห้ามอ้างว่า cancelled/completed/reattached
- ใช้ test-first: ต้องเห็น focused RED จาก behavior ใหม่ก่อนแก้ production และเห็น GREEN หลังแก้
- รักษา user-owned changes; stage/commit เฉพาะไฟล์ของแผนนี้ และห้าม reset/stash/broad format
- ปลายทาง Git คือ `dev` เท่านั้น; build ด้วย `--publish never`; ห้าม tag/publish/release

## Phase 3 — Operational and Governed `agent_swarm_run`

### Fixed public MCP contract

The dedicated tool uses a strict discriminated union; unknown keys are rejected. `workspaceId` reuses the repository `WorkspaceIdSchema`, `swarmId` is a UUID generated by the service, and every operation is owner-scoped from the trusted MCP actor rather than an input owner field.

| Operation | Exact request fields and bounds | Exact bounded response |
| --- | --- | --- |
| `start` | `{ operation:'start', workspaceId, idempotencyKey, accessMode:'read_only', tasks, maxConcurrency? }`; `idempotencyKey` UUID; `tasks` 1–4 unique entries; `maxConcurrency` integer 1–4 and no greater than task count, default 2 | `AgentSwarmSnapshot` with at most 4 task snapshots; retrying the same owner/workspace/key returns the same swarm and never launches extra quota work |
| start task | `{ id, prompt, dependsOn? }`; `id` matches `^[A-Za-z0-9][A-Za-z0-9_-]{0,63}$`; `prompt` nonblank and at most 32 KiB UTF-8; `dependsOn` at most 3 unique task IDs, cannot self-reference, all IDs must exist, whole graph must be acyclic | Prompt is accepted for launch but never returned or persisted; snapshot exposes only task ID, dependency IDs, state, timestamps, result availability and a redacted error no longer than 2,048 chars |
| `status` | `{ operation:'status', workspaceId, swarmId }` | One `AgentSwarmSnapshot`; task array maximum 4; no prompt, OS PID, command line or cross-owner information |
| `result` | `{ operation:'result', workspaceId, swarmId, taskId, cursor?, maxBytes? }`; `taskId` uses the task-ID regex; opaque cursor max 128 chars; `maxBytes` integer 1–16,384, default 8,192 | `{ swarmId, taskId, state, text, nextCursor?, eof }`; `text` at most requested UTF-8 bytes and output is redacted before persistence/return |
| `cancel` | `{ operation:'cancel', workspaceId, swarmId }` | Owner-scoped snapshot with one terminal/cancel outcome per task; repeated cancel is idempotent and never targets an unverified/restarted PID |
| `list` | `{ operation:'list', workspaceId, cursor?, limit? }`; opaque cursor max 128 chars; `limit` integer 1–50, default 20 | `{ items, nextCursor? }`; at most 50 owner-visible swarm summaries, each without task output/prompt/process identity |

`AgentSwarmSnapshot.state` is exactly `queued | running | completed | failed | cancelled | termination_unverified`; task state is exactly `blocked | queued | running | completed | failed | cancelled | termination_unverified`. Timestamps are ISO-8601 strings, error strings are redacted/bounded, result pages never split invalid UTF-8, and total stored output per task is capped at 1 MiB with an explicit `outputTruncated` flag. Reaching that storage cap does not hide task identity/state and is distinct from log-item completeness elsewhere in this plan.
